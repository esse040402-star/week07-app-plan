# 개인 앱 제안서

앱 이름: 나중에 노트 (LaterNote)
작성·수정 날짜: 2026-11-02

구현 전 기획 문서입니다. 앱 코드·실행 결과·사용자 조사 결과는 아직 없습니다.

## 1. 문제·사용자·핵심 가치

- 첫 사용자와 사용 순간: 수업·이동 중에 "이건 나중에 해야지" 하고 떠올린 대학생(본인). 그 자리에서 바로 처리할 수 없는 순간.
- 현재 해결 방법과 불편: 따로 적지 않고 머릿속으로만 "나중에 해야지" 하고 넘긴다. 그러다 정작 해야 할 때 까먹는다.
- 확인한 사실: 본인이 "나중에 해야지 하고 생각해 놓고 까먹는" 경험이 있음(본인 경험). 다른 사람은 조사하지 않음.
- 아직 확인할 가설과 질문: 떠오른 순간 몇 초 안에 적을 수 있으면 머릿속에만 두지 않을 것이다. → "나중에 해야지 한 일을 적지 않는 이유가 귀찮아서인가?"
- 앱 사용 후 얻을 핵심 도움: 떠오른 일을 바로 짧게 적어 두고, 나중에 앱을 열면 아직 안 한 일을 한곳에서 확인한다.
- 사용자 스토리: 할 일이 갑자기 떠오른 대학생이 그 일을 바로 적어 두어서, 나중에 까먹지 않고 처리하고 싶다.

## 2. MVP와 범위

| 기능 | 필수·보류·제외 | 이유 |
| --- | --- | --- |
| 할 일 빠르게 입력·추가 | 필수 | 머릿속에만 두지 않게 하는 핵심 행동 |
| 아직 안 한 일 목록·완료 표시 | 필수 | 나중에 열었을 때 남은 일을 확인하는 수단 |
| 앱을 다시 열어도 기록 유지 | 필수 | 나중에 보려고 적는 앱이라 사라지면 의미 없음 |
| 알림 | 보류 | 권한·패키지가 필요해 첫 흐름 확인 뒤 검토 |
| 날짜 지정·검색 | 보류 | 기본 흐름이 먼저 |
| 로그인·서버 동기화 | 제외 | 계정·서버 제외 제약 |

## 3. 제약과 결정

- 실행 환경과 확인 상태: Flutter 웹(Chrome) 계획. 실제 실행은 아직 안 함.
- 시간·인원·사용할 기술: 학생 1명, 배운 위젯과 StatefulWidget 상태 처리.
- 저장 위치와 유지 기간: 기기(브라우저) 로컬 저장. 앱을 닫았다 열어도 유지.
- 외부 서비스와 개인정보 범위: 계정·서버·유료 API 없음. 가상 할 일만 사용.
- 중요한 선택: 메모리 목록 / 기기 저장 / 서버 저장 중 **기기 저장** 선택. 메모리 목록은 재시작하면 사라져 "나중에" 볼 수 없고, 서버는 제약 위반. 영향: 저장 패키지(shared_preferences 후보) 1개와 읽기 실패 처리가 필요.
- 개발 규칙: lowerCamelCase 이름(analyze·스타일 대조), 빈 입력 검사는 한 곳에서만(공백 입력 실행), 변경 뒤 `flutter analyze` + 실제 실행.

## 4. 화면·데이터·상태

- 핵심 흐름: [앱 열기] → [할 일 입력·추가] → [나중에 다시 열어 확인하고 완료 표시]

| 화면·영역 | 사용자 행동 | 바뀌는 값·다음 상태 |
| --- | --- | --- |
| 입력 영역 | 내용 입력 후 추가 | 새 항목 추가·저장, 입력란 비움 |
| 할 일 목록 | 완료 표시 | 해당 id의 isDone=true, 목록에서 완료로 구분 |

| 데이터 필드 | 자료형 | 예시 | 규칙 |
| --- | --- | --- | --- |
| id | int | 1 | 항목마다 다름 |
| text | String | '택배 반품 신청' | trim() 후 비어 있으면 거절 |
| createdAt | DateTime | 2026-11-02 14:10 | 추가한 시각, 정렬용 |
| isDone | bool | false | 완료 시 true |

빈 상태·잘못된 입력·실패 안내: 항목 0개면 "떠오른 일을 적어 두세요", 공백 입력이면 "내용을 입력하세요", 저장소 읽기 실패면 오류 안내와 다시 시도.

## 5. 앱 인수 조건

| ID | 시작 상태와 행동 | 기대 결과 | 확인 방법·증거 | 실제 상태 |
| --- | --- | --- | --- | --- |
| AC1 | 항목 0개 → '택배 반품 신청' 입력 후 추가 | 목록에 1개 표시, 입력란 비워짐 | 목록·항목 수 확인 | 미실행 |
| AC2 | 항목 2개 → 공백 세 칸 입력 후 추가 | 안내 표시, 항목 수 2개 유지 | 안내와 항목 수 함께 확인 | 미실행 |
| AC3 | 항목 A·B → A 완료 표시 | A만 완료로 바뀜 | A·B 상태 비교 | 미실행 |
| AC4 | 항목 0개로 앱 열기 | 빈 목록 안내 표시 | 첫 화면 확인 | 미실행 |
| AC5 | 항목 1개 추가 → 새로고침 | 같은 항목 다시 표시 | 새로고침 전후 비교 | 미실행 |

실제로 실행하기 전에는 통과로 바꾸지 않습니다.

미정: 내용 최대 길이, 완료 항목을 언제까지 보여 줄지.
